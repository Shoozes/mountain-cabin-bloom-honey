# Project handoff

Use this workflow only for a requested person-to-person handoff. Queue-item
completion already archived or removed the selected item after its Done when
was proven; this record does not own that transition.

Before handing off, write a compact record containing:

1. Goal and current lifecycle stage.
2. Summary-bank group(s) loaded and why they are sufficient.
3. What changed, why, where, and how.
4. Commands run and proof paths.
5. Known pitfalls, edge cases, and unresolved risks.
6. The next safe action and its exact Done when, only when real work or an
   external blocker remains.

Do not imply that a mocked, static, or template-level check proves an application runtime. Do not ask the next pass to rediscover repository identity when the source documents already own it.
Do not publish, manufacture follow-up work, or update durable documents merely
to record that they were reviewed.

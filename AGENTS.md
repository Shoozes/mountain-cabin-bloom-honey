# Grout Shader project guidance

This is an existing React/TanStack Start/Vite texture-authoring repository,
currently developed locally on Windows. Gknome owns its project/workflow
contracts; it does not replace the app framework or hosting adapters.

## Context and ownership

Read `summary_bank.json` as the route map after applicable global instructions.
Load the smallest relevant groups and their actual source contents. Expand to
affected consumers/tests and unrouted changes. Do not run every context command
as a routine chain or treat a pack summary as source proof.

- Real product source: `src/`; preserve route URLs, recipes and export formats.
- Product bakers and tests: `scripts/`, `src/**/*.test.*`; foundation tests:
  `tests/foundation/`. A placeholder source tree is not another app.
- Project identity/runtime/tasks: `.tools/project.json` and typed spec/state.
- Active selected work: `docs/work/queue/`; future work/acceptance:
  `docs/TODO.md`. Existing dated proof remains historical at its source identity.
- Authoring contracts: `docs/look-dev/texture-authoring.md`,
  `docs/look-dev/texture-tools.md`, and the relevant retro terrain guide.

Preserve existing staged, modified and untracked work. Use explicit task-file
allowlists for publication. Do not reset, clean, discard, bulk delete or absorb
other owner work. Do not read, print, hash, copy or stage credential material.

## Product runtime

Keep `package.json`, `vite.config.ts`, `tsconfig.json` and public authoring
commands in place. Standard npm commands launch Vite directly; Gknome routes
those same commands. Dev binds `0.0.0.0:8080`. Both builds prerender the app to
`dist/client`; Pages retains its existing repository base path. There is no
Grok preview shell, platform PWA injector, auth/environment wrapper or Vercel/
Nitro hosting adapter. Do not reintroduce retired host integration implicitly.

Lint and formatting configuration live in `.tools/config/`. `src/` is the only
product source tree; the old `source/` pointer was explicitly retired. Historical
screenshots live in `docs/look-dev/screenshots/`. The original foundation
provenance remains an immutable historical snapshot; current layout changes are
recorded in the root-cleanup work record rather than rewriting provenance.

## Verification and craft

Use relevant focused checks first, then required gates at closeout:
`npm test`, `npm run typecheck`, `npm run lint`, `npm run build` and
`npm run build:pages`. Browser proof must exercise actual behavior on dev and
built output; inspect desktop/mobile captures and console results. Reuse proof
only while relevant source inputs match. Record exact failures and their owners;
do not repeat an unchanged failing command or weaken a required gate.

Pixel art uses deliberate native clusters, finite palettes and integer viewing.
Palette quantization alone is not art acceptance. Preserve original recipes and
legacy output unless the selected outcome explicitly changes them. Purchased
pixels, extracted ramps and modified purchased art stay outside fixtures/exports.
Generated artwork remains unapproved until the owner accepts it. Engine/PBR
receiving and runtime anti-tiling are separately owned outcomes.

## Cleanup and publication

Generated bakes/proof live in ignored `.artifacts/`; runtime owner receipts
live in ignored `.runtime/`. Protect accepted/current proof and unknown or
active owners. For long-running services record PID, exact start time, executable,
endpoint, lifetime and shutdown route; identity-check before stopping owned
resources. Deliberately retained live previews remain retained. See
`docs/dev/RUNTIME_LIFECYCLE.md` and the global proof/storage standard.

An explicit paired Closeout/Publish request authorizes its named verified batch.
Use only the repository's documented guarded `.tools/gitpush.ps1` route; never
raw push, force, merge/rebase or create publication workarounds. Preserve guard
failures and keep security checks intact. The old OAuth-containing module was
retired opaquely under the standalone request; current scans and helper guards
still must pass. Saving progress
does not approve unfinished art. Deployment and releases require separate scope.

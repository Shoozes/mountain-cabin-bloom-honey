# mountain-cabin-bloom-honey Integrity Pass

Use this at Stage 8 after an MVP or LTS snapshot candidate exists.

## Identity and scope

- Project identity still matches implemented behavior.
- Non-goals and external ownership remain clear.
- Snapshot claims match actual proof.
- Stale roadmap or placeholder language is removed.

## Source of truth

- One authoritative file exists for each domain.
- Secondary docs link rather than redefine.
- Old names, paths, schemas, and compatibility aliases are inventoried.
- Generated or runtime state is not treated as source.

## Code and architecture

- Demo shortcuts are removed, isolated, or documented.
- Duplicated logic and configuration are reduced.
- Module boundaries match ownership.
- Cancellation, cleanup, error, and recovery paths are complete.
- Dependencies and runtime requirements are minimal and explicit.

## Safety

- Secret, path, byte, state, async, privilege, network, and dependency checks pass.
- Destructive operations are staged or reversible.
- Hardware capacity and fallback behavior are tested at supported targets.
- Install, update, rollback, and uninstall behavior is understood where applicable.

## Courtesy

- Setup and one-stop commands are current.
- Errors explain the next action.
- Context groups are focused and under budget.
- The repository is ready for the next developer or agent pass.
- Supported and unsupported platforms, hardware, and display conditions are explicit.

## Show

- User-facing and developer-facing flows feel intentional.
- Long operations expose progress and cancellation.
- Visual, motion, console, and proof surfaces meet the snapshot quality bar.
- No placeholder, janky, or inconsistent flow remains in the claimed path.

## Efficiency

- Benchmarks are repeatable and hardware-scoped.
- Material bottlenecks are measured before changes.
- Optimizations preserve Safety, Courtesy, and Show.
- Context, dependency, artifact, cache, and runtime footprints are understood.

## Proof and release

- Tests and benchmarks identify commands, versions, inputs, hardware, and outputs.
- Known limitations and rollback paths are documented.
- Snapshot artifacts have immutable identity and checksums.
- Pitfall ledger entries are closed, accepted, or explicitly deferred.

## Exit record

Record:

- snapshot version,
- integrity-pass date,
- exact tested commits or artifact hashes,
- pass, partial, or blocked status,
- remaining debt,
- next approved scope.
